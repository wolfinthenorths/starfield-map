# Протектрон — личный игровой контроллер Starfield

Telegram-бот с диалогами по кнопкам и мини-приложением. Игровые диалоги работают в личных чатах; группа ГМ принимает только команду привязки и решения по рапортам. Меню мини-приложения устанавливается через `setChatMenuButton`.

## Диалоги

- Ввод имени персонажа → сверка класса и степени по реестру → «Получить мистериум» → подтверждение → выдача 1/2/3 единиц (одна полная доза) → художественный ответ. Кнопка «Посмотреть выдачу» открывает анимацию уже зарегистрированной выдачи без повторного списания/записи.
- Мини-приложение: та же проверка реестра → анимация десяти готовых кадров сундука → запись выдачи в журнале. Действия в мини-приложении не создают сообщений в личном чате.
- «Повысить доступ» → выбор одной из 12 служб из архива Starfield → выбор уровня 2, 3 или 4 → обращение для будущего теста. Свободного ввода нет. Уровни разных служб учитываются отдельно; общего служебного уровня нет. Ω не является пятым уровнем и в обычной аттестации не предлагается.
- Справочные ответы подготовлены заранее и основаны на утверждённых правилах. Непредусмотренные вопросы направляют игрока к мастеру.
- Игрок указывает имя из реестра без подтверждения ГМ; принадлежность имени игроку основана на доверии. Telegram ID идентифицирует автора записи журнала. История привязана к Telegram user ID.

## Что учитывается

Сервис хранит выдачи и запросы на доступ. В выдаче фиксируются username Telegram на момент получения, полная доза (1/2/3 единицы), Unix timestamp и дата/время с секундами по `Asia/Tomsk`. Если username отсутствует, сохраняется Telegram ID. Получение не означает приём. Счётчик ходов, приём препарата, инвентарь чарки и прохождение испытаний пока не подключены. Рапорты на выдачу препарата иному лицу пересылаются в привязанную группу ГМ; согласование разрешает одну выдачу, запись в журнал появляется только после получения. Уведомления об одобрении действий из приложения остаются внутри приложения.

Каталог служб и названия уровней: `public/accesses.json`, источник — действующая «Система Допусков» на сайте архива. Будущие ссылки на тесты задаются секрет-free переменной `QUALIFICATION_TEST_URLS` в формате JSON: `{ "MED-2": "https://...", "TEC-3": "https://..." }`. До добавления ссылки бот сообщает, что тест будет доступен позже. Автоматического повышения допуска нет.

Google-таблица «ЖУРНАЛ ГУЛЕЙ» подключена как автоматически обновляемое представление постоянного журнала через `IMPORTDATA`. Выдачи немедленно фиксируются в SQLite; Google Sheets периодически перечитывает CSV, с собственной задержкой обновления (обычно проверка каждый час при открытом документе). Точное время выдачи записывается в момент действия, а не во время обновления таблицы. Ячейку с формулой импорта и её результирующий диапазон нельзя заполнять вручную — ручные изменения выполняются в личных чарках, как предусмотрено пользователем.

CSV доступен только по непредсказуемому ключу `JOURNAL_TOKEN`; он даёт только чтение трёх колонок журнала и не является токеном Telegram. Ключ находится в переменных Railway и формуле приватной таблицы, в репозиторий не включается. Его нельзя публиковать: обладатель URL может прочитать журнал. Выдачи, сохранённые до появления username в журнале, обозначаются Telegram ID без выдумывания исторического username.

## Серверное соединение с Google Sheets

Реестр персонажей подключён отдельным Apps Script (`sheets-bridge.gs`). `SHEETS_BRIDGE_URL` и `SHEETS_BRIDGE_SECRET` задаются только на сервере Railway; соответствующий ключ `BRIDGE_SECRET` находится в свойствах скрипта Google. Не включать ключ в код, URL, клиентские файлы или журнал. Запрос подписывается HMAC-SHA256 по точным UTF-8 байтам `timestamp + "\n" + payload`, срок действия — 60 секунд. Без подписи доступны только название и версия сервиса, не данные таблицы.

Версия 2 добавляет каталог и получение перков. Защищённые операции ограничены конкретным реестром, его балансом и журналом «Перки»; произвольных адресов таблиц и диапазонов в API нет. Протокол использует ASCII-экранирование JSON-полезной нагрузки, чтобы кириллица не менялась при проверке подписи. Сервер повторяет проверку соединения раз в час, при ошибке — через минуту; `/health` показывает только состояние соединения и модуля развития. Пустой баланс возвращается как «не задан», а не как ноль.

### Покупки и бесплатные выборы

В `Лист1`: F — **доступный остаток** очков навыков, G — текущий уровень персонажа 0–9, H — постоянный UUID персонажа (скрыт; не изменять при переименовании). UUID заполняется для новых строк автоматически, уровень и начисления не угадываются. Колонка с формулой общего начисления не заменяется числом: платные покупки блокируются, пока вместо неё не будет доступного остатка. Не изменять баланс или порядок строк одновременно с оформлением покупки: блокировка скрипта сериализует действия робота, но не ручные правки людей в Google Sheets.

Покупка проходит сразу, без согласования ГМ, по решению владельца проекта. Игрок видит подтверждение цены и остатка и отмечает завершение сцены/этапа; покупки в бою правилами не предусмотрены. Дополнительный малый перк стоит 2 очка; «Кровавое месиво» — 6; остальные четыре крупных — по 4. Цена проверяется независимо на сервере и в Google; версии каталогов сверяются перед списанием. Получение каждого перка возможно только один раз для одного персонажа, независимо от аккаунта Telegram.

Отдельная кнопка «Выбрать за уровень» расходует один из бесплатных выборов, но не очки навыков. Доступно: текущий уровень минус число уже оформленных бесплатных выборов. Пустой уровень не означает нулевой и блокирует только бесплатный выбор. Крупный перк бесплатно выбрать нельзя. Классовый перк выдаётся при создании и показывается отдельно; для Жителя в роботе один раз закрепляются два разных навыка. Личные таблицы характеристик не редактируются автоматически; бонусы отмечаются в них отдельно.

Лист «Перки» содержит персонажа, перк, способ получения («Покупка», «За уровень», «Классовый»), потраченные очки, остаток, время по Томску и Telegram автора. В скрытых технических колонках — неизменяемый ID операции, UUID персонажа, ID перка, время UTC и выбранные навыки. Не удалять и не редактировать служебные записи вручную. До включения робота полученные перки не были импортированы: их перенос требует отдельного списка от администрации.

Google Sheets API `batchUpdate` сохраняет списание из F и строку владения в одной атомарной операции, под `LockService.getScriptLock`. Повтор с тем же ID возвращает прежний результат, не списывая повторно. При потерянном ответе приложение сохраняет номер обращения в localStorage и повторяет его; новая покупка временно блокируется. Повторный новый номер для уже полученного перка также не списывает очки. После подтверждения Google квитанции зеркалируются в SQLite (`perk_receipts`) и личный журнал событий, включая резервные копии. Если Google-журнал потерял уже зеркалированную запись, модуль блокирует новые покупки до восстановления; медицинские выдачи от этого не зависят.

Команда `/perks` и кнопка «Перки персонажа» открывают модуль. Действия в приложении не отправляют сообщения в личный чат или чат ГМ. В карточке и на главном экране показаны уровень и актуальный доступный остаток; после покупки значения обновляются из результата операции. Активные перки не удаляются после применения и не продаются заново в новой главе: учёт применений остаётся игровым.

### Совместимость открытия

Официальный `telegram-web-app.js` обслуживается локально без изменений; `ready()` вызывается до загрузки спрайтов и запросов к API, чтобы не задерживать снятие загрузочного экрана клиента Telegram. Сервер поддерживает `HEAD` с теми же заголовками и без тела, вместо 501. Версии CSS/JS в HTML предотвращают смешение старого интерфейса с новой логикой. Сам Telegram Desktop в этой среде не воспроизводился; эти изменения исправляют найденные препятствия, но не доказывают причину конкретного белого окна.

Скрипт выполняется от владельца. Разрешение Google на таблицы может быть шире одной таблицы; код жёстко ограничен указанным реестром и двумя операциями. Отозвать доступ можно в аккаунте Google, закрыть веб-развертывание — в Apps Script. При восстановлении конфигурации использовать сохранённый URL развертывания и новый случайный ключ не менее 32 символов, одинаковый в Google и Railway; подпись Telegram для этого не используется.

## Запуск

Python 3.12, `pip install -r requirements.txt`, затем `python server.py`. boto3 используется только для отдельного хранилища резервных копий.

Production-переменные:

- `BOT_TOKEN` — секрет Telegram, только в переменных сервиса.
- `APP_URL` — публичный HTTPS URL приложения.
- `DATA_DIR=/data` — **обязательно постоянный том**, смонтированный на `/data`.
- `PORT=8080` — порт HTTP.
- `JOURNAL_TOKEN` — отдельный секрет чтения журнала Google-таблицей.
- `MYSTERIUM_SPREADSHEET_ID` — идентификатор связанной Google-таблицы (метаданные размещения).

SQLite с WAL хранится в постоянном томе. Обновления Telegram и кнопки выдачи защищены от повторной обработки. API проверяет HMAC Telegram initData, идентификатор пользователя и возраст подписи. Секреты не попадают в исходники, фронтенд или логи.

Отправка реплик идёт через устойчивый журнал исходящих сообщений с повторами при сбоях. При неоднозначном сетевом тайм-ауте Telegram возможен повтор сообщения: Bot API не предоставляет идемпотентный ключ для sendMessage. Само событие выдачи при этом не дублируется.

Приложение использует webhook с секретным заголовком. Сервис на Railway должен работать в одной реплике; база и очередь не предназначены для нескольких параллельных экземпляров. Том переживает обновления сервиса. Резервные копии SQLite создаются каждые 6 часов через Online Backup API, а ежедневные копии сохраняются в отдельном приватном объектном хранилище.

Без Telegram-подписи доступен только просмотр интерфейса и справочника; выдача и записи отключены.

## Проверка

`python -m unittest discover -s tests -v` проверяет подписи, повторную обработку, выдачу нужной дозы, изоляцию пользователей и сценарий доступа.

Все готовые графические и звуковые материалы перечислены в `public/assets/SOURCES.md`. Генерация изображений не использовалась.

## Реестр и группа ГМ

`ROSTER_URL` — CSV-экспорт реестра; проверяется каждые 60 секунд. Заголовки: «Имя персонажа», «Класс», «Степень», «Telegram-аккаунт», «Telegram ID». Для личной выдачи допустим класс «Гуль» и степень I/II/III. Колонки Telegram оставлены для совместимости и не ограничивают регистрацию; игрок указывает имя самостоятельно. При недоступном реестре выдачи блокируются.

`GM_USERNAMES=VaultTecGm,gj0xl`; `GM_BIND_CODE` — случайный код привязки. Один из этих ГМ отправляет `/bind_gm@ptotectoronbot КОД` в нужной группе или теме. Бот сохраняет идентификатор группы/темы и подтверждает привязку. После первого разрешённого действия ГМ закрепляется по Telegram ID. Повторная привязка к другой группе запрещена.

«Согласование выдачи дозы для иного лица» → выбор другого гуля из реестра → рапорт → кнопки «Согласовать / Отклонить» в группе ГМ → получение одной согласованной дозы. Повторное нажатие не создаёт новую выдачу. Изменение степени получателя после согласования требует нового рапорта. Реестр определяет права, поэтому доступ на его редактирование должен оставаться у администрации.

## Резервные копии и восстановление

Локальные копии `/data/backups/` создаются каждые 6 часов и хранятся 7 дней. Каждый день новая копия отправляется в отдельный приватный bucket `protectoron-backups` (регион ams), вне основного диска бота. Отдельные копии хранятся 30 дней. При запуске новая копия создаётся сразу, если предыдущая уже устарела; расписание сохраняется между перезапусками в `/data/backup-status.json`.

Каждая локальная копия проходит `PRAGMA quick_check`. Каждая отдельная копия скачивается обратно, сравнивается по SHA-256, восстанавливается во временную базу и проверяется по целостности и количеству записей во всех таблицах. Только после этого сохранение признаётся успешным. При сбое предыдущие копии сохраняются, попытки повторяются каждые 5 минут, в группе ГМ появляется уведомление об ошибке (одно на непрерывную серию сбоев).

Переменные `BACKUP_S3_ENDPOINT`, `BACKUP_S3_BUCKET`, `BACKUP_S3_REGION`, `BACKUP_S3_ACCESS_KEY_ID`, `BACKUP_S3_SECRET_ACCESS_KEY` ссылаются на переменные bucket через Railway references; `BACKUP_S3_URL_STYLE=virtual-host`. Bucket закрытый, секреты не передаются в Telegram, клиентское приложение или репозиторий.

В личном чате ГМ доступны `/backupdb` (создаёт и проверяет обе копии немедленно) и `/dbstats` (количество записей и время последних успешных копий по Томску). Игрокам эти команды недоступны; в группе команды предлагают открыть личный чат.

Production отказывается запускаться без смонтированного постоянного диска. Если файл базы исчез, но резервные копии существуют, сервис не создаёт пустую базу взамен потерянной. Для восстановления: остановить сервис; скачать нужный объект из bucket; проверить `backups.verify_snapshot(path)`; восстановить через `backups.restore_snapshot(source, destination)` в НОВЫЙ файл; сохранить текущую базу и WAL/SHM отдельно и затем заменить их проверенной восстановленной базой. Повторно не отправлять доставленные раньше сообщения: перед запуском после отката проверить таблицу `outbox` и отметить восстановленные старые исходящие как обработанные. Автоматического отката базы при запуске нет.

Копии защищают от потери основного диска, однако остаются в той же учётной записи Railway. События после последней сохранившейся копии не восстановятся: локально окно до 6 часов, при потере диска — до 24 часов при исправном отдельном сохранении. О сбоях внешнего сохранения сообщают `/dbstats`, `/health` и группа ГМ.
