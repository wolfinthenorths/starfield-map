# Протектрон — личный игровой контроллер Starfield

Telegram-бот с диалогами по кнопкам и мини-приложением. Сервис работает только в личных чатах; групповые обновления игнорируются. Меню мини-приложения устанавливается через `setChatMenuButton`.

## Диалоги

- «Получить мистериум» → вопрос о степени гулификации → I/II/III → выдача 1/2/3 единиц (одна полная доза) → художественный ответ. Кнопка «Посмотреть выдачу» открывает анимацию уже зарегистрированной выдачи без повторного списания/записи.
- Мини-приложение: тот же выбор степени → анимация десяти готовых кадров сундука → сообщение бота в личном чате.
- «Повысить доступ» → вопрос о нужном доступе → следующий системный уровень либо свободное название → сохранённая заявка на отдельное тестирование. Автоматического повышения нет. Стартовый доступ 1; уровень персонажа 0 учитывается отдельно и не моделируется здесь.
- Справочные ответы подготовлены заранее и основаны на утверждённых правилах. Непредусмотренные вопросы направляют игрока к мастеру.
- Имя персонажа меняется отдельно от имени Telegram. История привязана к Telegram user ID.

## Что учитывается

Сервис хранит выдачи и запросы на доступ. Получение не означает приём. Счётчик ходов, приём препарата, инвентарь чарки и прохождение испытаний пока не подключены. Точные виды доступа и сценарии испытаний должны быть добавлены после согласования; для остальных видов имеется свободное поле. Заявки сохраняются в журнале игрока, автоматической пересылки администрации нет.

## Запуск

Python 3.12, сторонних зависимостей нет. `python server.py`.

Production-переменные:

- `BOT_TOKEN` — секрет Telegram, только в переменных сервиса.
- `APP_URL` — публичный HTTPS URL приложения.
- `DATA_DIR=/data` — **обязательно постоянный том**, смонтированный на `/data`.
- `PORT=8080` — порт HTTP.

SQLite с WAL хранится в постоянном томе. Обновления Telegram и кнопки выдачи защищены от повторной обработки. API проверяет HMAC Telegram initData, идентификатор пользователя и возраст подписи. Секреты не попадают в исходники, фронтенд или логи.

Отправка реплик идёт через устойчивый журнал исходящих сообщений с повторами при сбоях. При неоднозначном сетевом тайм-ауте Telegram возможен повтор сообщения: Bot API не предоставляет идемпотентный ключ для sendMessage. Само событие выдачи при этом не дублируется.

Приложение использует webhook с секретным заголовком. Сервис на Railway должен работать в одной реплике; база и очередь не предназначены для нескольких параллельных экземпляров. Том переживает обновления сервиса, но резервные копии тома необходимо настраивать отдельно.

Без Telegram-подписи доступен только просмотр интерфейса и справочника; выдача и записи отключены.

## Проверка

`python -m unittest discover -s tests -v` проверяет подписи, повторную обработку, выдачу нужной дозы, изоляцию пользователей и сценарий доступа.

Все готовые графические и звуковые материалы перечислены в `public/assets/SOURCES.md`. Генерация изображений не использовалась.
